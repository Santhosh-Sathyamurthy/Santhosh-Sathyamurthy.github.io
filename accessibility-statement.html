Accessibility Statement

Conformance status

This site is designed and built to conform to WCAG 2.1 Level AA, as required by GIGW 3.0 (Guidelines for Indian Government Websites and Apps) and the Rights of Persons with Disabilities Act, 2016. "Conformance" means we have targeted these standards throughout design and development; it has not yet been through a third-party STQC accessibility audit, which we recommend before this site goes live on the institute's domain.

What we've built in

  • A "Skip to main content" link on every page for keyboard and screen-reader users.
  • Visible keyboard focus on every interactive element, never removed with outline:none.
  • Text resize controls (A / A+ / A++) and a dark-mode toggle in the utility bar, both remembered across pages.
  • Colour is never the only signal: category tags carry text labels alongside colour coding.
  • All colour pairings used for text meet a 4.5:1 contrast ratio (3:1 for large text).
  • prefers-reduced-motion is respected sitewide, and no content relies on hover-only interaction.
  • Forms have explicit <label>s, grouped <fieldset>s, and validation errors that are announced, not just shown in colour.
  • Semantic landmarks (header, nav, main, footer) and a logical heading structure on every page.

Known limitations

We believe in disclosing gaps rather than hiding them:

  • The generated pattern art standing in for club/event photography is decorative and marked as such to screen readers, but has not been tested with real assistive-technology users.
  • This build has not yet had a formal screen-reader pass with NVDA/JAWS/VoiceOver or a manual keyboard-only walkthrough by someone with a disability. Both are recommended before launch (see the UX4G Handbook's Build-stage accessibility testing guidance).
  • Multilingual support (Hindi/Telugu, as offered on the main institute site) is not yet implemented here.
  • Navigation and footer currently require JavaScript (see "Technical specifications" below), and this should be moved to a server-side include before production deployment.

Feedback

If you encounter an accessibility barrier on this site, please tell us through the contact form (choose "Something else" and mention "Accessibility"), or by email at studentactivities@iisertirupati.ac.in. Please include the page URL and, if possible, the assistive technology you were using; we aim to acknowledge reports within 5 working days.

Technical specifications

Accessibility relies on the following technologies: HTML5, CSS3 (with custom properties), and JavaScript. Each page's own content (headings, text, forms) is present in the HTML source and readable without JavaScript. The header, footer and navigation, however, are loaded via JavaScript from shared partial files for maintainability (see assets/js/include-partials.js), so a visitor with JavaScript disabled will not currently see the site's navigation or footer. This is a known trade-off, listed here rather than hidden: before this site is deployed on the institute's production server, we recommend moving the header/footer include to a server-side mechanism (the server's templating system, PHP includes, or a static-site build step) so navigation works with JavaScript off, while keeping the same "edit it in one place" benefit for maintainers.
